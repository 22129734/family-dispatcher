# Семейный диспетчер

**Поручения, которые доходят и выполняются.** Скажите, что нужно сделать, — диспетчер передаст дело второму взрослому, тот ответит «Беру» прямо из уведомления, а вы увидите, что дело взято. Без «я же тебе писала».

**Открыть:** https://семейныйдиспетчер.рф

Проект команды в акселераторе **Sber500 x Disrupt** (трек «Разработаю продукт с нуля», Social & Family).

## Проблема

Мы провели 21 интервью с семьями ([итоги](docs/research/README.md)). Главная боль — не распределение дел, а **контроль поручений**: организатор быта (чаще мама) передаёт дело супругу через мессенджер, где оно теряется среди переписки, — и потом сама держит его в голове, перепроверяет и напоминает.

- **Персона** — [docs/research/persona.md](docs/research/persona.md)
- **JTBD, карта сценариев, приоритизация RICE** — [docs/research/jtbd-scenarios-rice.md](docs/research/jtbd-scenarios-rice.md)

## Как работает

```
Сказать или написать  →  Задача с исполнителем и сроком  →  Push исполнителю  →  «Беру» / «Не могу»  →  «Сделано»  →  Автор видит статус
```

1. **Поручить.** Организатор пишет фразу: «Завтра в 6 забрать Машу с танцев». LLM разбирает её в задачу — название, срок, повтор, нужна ли машина.
2. **Доставить.** Задача уходит второму взрослому (для поездок — тому, у кого машина) push-уведомлением с кнопками.
3. **Получить ответ.** «Беру» — в одно касание из уведомления, без открытия приложения. «Не могу» — с причиной, задача возвращается автору.
4. **Закрыть.** Исполнитель отмечает «Сделано», автор получает уведомление.

Вход — по номеру телефона через звонок, без паролей и SMS-кодов. Приложение ставится на экран телефона как обычное (PWA).

## Архитектура

```
Телефон (PWA + service worker)
        │ HTTPS
        ▼
Caddy (TLS) ──► FastAPI ──► PostgreSQL
                  │
                  ├──► LLM программы Sber500 (GigaChat 3.5): фраза → задача
                  ├──► SMS.RU: вход звонком
                  └──► Web Push (VAPID): поручения и ответы
```

**LLM понимает язык, но не решает за семью:** модель разбирает фразу в задачу, а исполнителя выбирают простые правила. Без модели работает резервный разбор правилами — продукт не ломается.

Схема, сценарий, развёртывание и наблюдаемость — [docs/architecture.md](docs/architecture.md).

## Стек

- **Клиент:** React 19, TypeScript, Vite, Tailwind CSS 4, PWA (service worker, Web Push)
- **Бэкенд:** Python 3.13, FastAPI, Pydantic v2, SQLAlchemy 2, Alembic, pywebpush
- **Данные:** PostgreSQL 17
- **ИИ:** LLM из инфраструктуры программы через OpenAI-совместимый API (GigaChat 3.5, function calling)
- **Инфраструктура:** Docker Compose, Caddy (HTTPS Let's Encrypt), VPS в России
- **Внешние сервисы:** SMS.RU (вход звонком), push-сервисы браузеров

## Метрики

Каждое действие пользователя пишется в события, каждое обращение к компоненту (LLM, push, вход и т. д.) — в журнал обращений. Отсюда считаются DAU, обращения на DAU и стоимость LLM на DAU — `GET /api/v1/analytics/daily`. Подробнее — [docs/web-mvp.md → Аналитика](docs/web-mvp.md#аналитика-и-обращения).

## Быстрый старт

Нужны Python 3.12+ и Node.js 20+. Ключи не обязательны: без них задачи разбирают правила, вход подтверждается сразу, push выключены.

```bash
git clone https://github.com/22129734/family-dispatcher.git
cd family-dispatcher

# Backend — http://localhost:8000/docs
cd backend
python -m venv .venv && source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
cp ../.env.example .env
uvicorn app.main:app --reload

# Web — http://localhost:5173 (в другом терминале)
cd web
npm install
npm run dev
```

Тесты и линтер:

```bash
cd backend && pytest && ruff check . && ruff format --check .
cd web && npm run build
```

Развёртывание на сервере (Docker Compose) — [docs/architecture.md → Развёртывание](docs/architecture.md#развёртывание).
