# Архитектура

## Принцип, вокруг которого построена система

**LLM не планирует расписание.** GigaChat отвечает за понимание естественной речи и за формулировку сообщений человеку. За то, кому достанется задача, отвечает детерминированный движок распределения.

Это разделение — не техническая деталь, а продуктовое требование. Семейное расписание — зона повышенного доверия: назначение должно быть воспроизводимым, объяснимым и оспариваемым. Если задачи раздаёт языковая модель, семья получает решение, которое нельзя проверить и на которое нельзя пожаловаться. Плюс LLM систематически ошибается в арифметике времени.

## Слои

### 1. Каналы ввода

| Канал | Что даёт |
|---|---|
| Голосовое сообщение в приложении | Основной сценарий: руки заняты, ребёнок рядом |
| Пересылка сообщения из чата | Задачи из родительских чатов и переписки с супругом |
| Фото записки / объявления из школы | OCR + извлечение |
| Подключённый календарь (CalDAV / ICS) | Существующие события как контекст загруженности |
| Навык Алисы / SberBoom | Голосовой ввод без телефона в руках |
| Telegram-бот | Быстрый вход без установки приложения |

### 2. Понимание — `TaskExtractor`

GigaChat вызывается с описанием функции `create_task` (function calling). Модель возвращает структурированные аргументы, а не текст:

```
title, beneficiary, due_at, duration_minutes,
priority, recurrence, requires_car, location, clarifying_question
```

Если сообщение неоднозначно, модель обязана вернуть **один** уточняющий вопрос, а не додумать детали. Это отличает продукт от ассистентов, которые уверенно ставят задачу не на тот день.

При недоступности LLM работает детерминированный резервный разбор (относительные даты, маркеры срочности, повторяемости и необходимости автомобиля). Продукт деградирует, но не ломается.

### 3. Распределение — `Allocator`

Двухфазный алгоритм.

**Фаза 1 — жёсткие ограничения.** Кандидат отбрасывается, если:
- задача требует автомобиля, а у человека его нет;
- недельная ёмкость исчерпана;
- время задачи пересекается с занятым окном в расписании.

**Фаза 2 — взвешенная оценка** оставшихся кандидатов:

| Компонент | Вес | Смысл |
|---|---|---|
| Баланс нагрузки | 0.55 | Насколько человек недогружен относительно среднего по семье |
| Запас ёмкости | 0.30 | Сколько свободного ресурса остаётся |
| Предпочтения | 0.15 | Штраф за задачи, которых человек избегает |

Приоритет баланса нагрузки — прямое следствие проблемы, которую мы решаем: перекос в сторону одного человека и есть невидимый труд.

Результат распределения содержит не только исполнителя, но и `rationale` — объяснение, сгенерированное GigaChat из технической причины, и `alternatives` — двух следующих кандидатов на случай отказа.

### 4. Индекс невидимого труда

`invisible_labour_index()` возвращает долю недельной нагрузки по каждому члену семьи. На этом строится еженедельный отчёт — ключевая механика вовлечения второго родителя и главный источник виральности продукта.

### 5. Напоминания и контроль

Celery + Redis: отложенные задачи на напоминания, периодический пересчёт плана, эскалация просроченного. При просрочке система не упрекает, а предлагает действие: перенести, разбить или передать тому, кто сейчас свободен — вместе с пересчитанным списком кандидатов.

## Хранение данных

- **PostgreSQL 16** — семьи, участники, задачи, расписания, история выполнения
- **pgvector** — «память семьи»: рутины и предпочтения для RAG-контекста при извлечении задач
- **Redis** — кэш, сессии, брокер очередей

Персональные данные хранятся и обрабатываются на территории РФ (Cloud.ru) в соответствии с 152-ФЗ. Чувствительные поля шифруются в покое, транспорт — TLS 1.3.

## Приватность

- Сообщения из чатов обрабатываются **только по явному opt-in** и только при явной пересылке. Фонового чтения переписки нет.
- Храним извлечённую задачу, а не исходный текст сообщения.
- RBAC по ролям в семье: взрослый, подросток, ребёнок — разные права на просмотр и назначение.

## Контроль качества AI

Golden-set из 200+ размеченных бытовых фраз на русском языке. Каждое изменение промптов прогоняется по нему в CI. Целевая точность извлечения задачи — не ниже 85%.

Стоимость LLM-вызовов контролируется маршрутизацией: повторяющиеся и шаблонные задачи обрабатываются правилами, простые кейсы уходят на GigaChat Lite, сложные — на Pro.
