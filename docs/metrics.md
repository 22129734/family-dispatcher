## Как считаем

- **Активный пользователь** — реальный пользователь: хотя бы раз прошёл целевой путь (нарастающим итогом на конец недели).
- **Вернувшийся** — реальный пользователь, который за неделю заходил в приложение хотя бы в два разных дня.
- **Запрос к LLM** — вызов модели приложением (разбор фразы, списки по отделам, дела со скриншота), журнал `component_calls`, вид `llm`. Генерация картинок для роликов в него не входит.
- **Обращение к компонентам** — вызов любого компонента решения в сценарии пользователя: LLM, навыки, инструменты, API решения, внешние API, хранилище, фоновая система. Полный список и что не считается — [web-mvp.md → Аналитика](web-mvp.md#аналитика-и-обращения).
- **Реальный пользователь** (Положение, п. 4.2.2) — выполнил целевой сценарий: взял дело («Беру»), отметил «Сделано» или «Я помню», либо его поручение выполнено. Код: [`backend/app/services/metrics.py`](../backend/app/services/metrics.py).
- **Всего пользователей** — зарегистрированные аккаунты без команды.
- **Кастдевы** — 21 интервью 01–04.10.2026, обезличенные выводы: [research/README.md](research/README.md).
- **Готовность MVP** — 100% с 12.10: продукт выпущен и работает у пользователей; оценка команды по требованиям этапа 1 и [истории разработки](https://github.com/22129734/family-dispatcher/commits/main).

## Как проверить

Ежедневная аналитика и журнал обращений доступны организаторам по ключу администратора:

- `GET /api/v1/analytics/daily` — DAU, действия и обращения к компонентам по дням;
- `GET /api/v1/analytics/component-calls.csv`, `GET /api/v1/analytics/events.csv` — выгрузки с обезличенным ID пользователя, источником трафика и стоимостью вызовов LLM.

Заголовок `X-Admin-Token`; ключ выдаём по запросу. Код — [`backend/app/api/analytics.py`](../backend/app/api/analytics.py).
