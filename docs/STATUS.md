## 2. Что изменилось после встречи с ментором (29.09)

Ментор развернул порядок работ: **сначала исследование, потом продукт.** Исходная идея — «семейный диспетчер, который справедливо распределяет дела» — рассматривается как гипотеза, а не как решение.

Задачи этапа, заведённые в трекер программы (связаны цепочкой «вход → выход»):

| Этап | Тип | Результат | Срок* |
|---|---|---|---|
| **1/3. Интервью** | Интервью | 20+ живых интервью; сегменты семей, где проблема острее и чаще | 12.10 |
| **2/3. Персона и проблема** | Гипотеза | Карточка целевой персоны и её главная проблема с подтверждением из интервью | 15.10 |
| **3/3. Прототип** | Функциональность | Прототип с обязательными функциями (must-have), каждая обоснована болью из интервью | 26.10 |

\* Сроки предварительные — сверить с согласованными в трекере.

Методика интервью — книга Роба Фитцпатрика «Спроси маму» (The Mom Test), рекомендована ментором.

## 3. Состояние исследования

**Проведено: 2 интервью из 20+.** Обезличенные выводы — [research/README.md](research/README.md).

Коротко:
- Оба респондента — мужчины-**исполнители**; организатор быта в обеих семьях — жена. Нужно опрашивать организаторов.
- Проблема **справедливого распределения не прозвучала** (гипотеза H-0 пока не подтверждается).
- Звучит **контроль выполнения**: срывы поручений (15–20% у Р1), контроль обязанностей и уроков подростка (Р2 — единственная эмоциональная боль).
- Задачи передаются в **мессенджерах** (VK, Telegram), семейных приложений не используют.

## 4. Состояние кода

Ветка **`feature/web-mvp`** (не смёржена в `main`, не запушена).

Сделан **веб-MVP, ориентированный на мобильные** (PWA), поверх существующего ядра (`TaskExtractor` + `Allocator`). Сквозной сценарий проверен в браузере на мобильном вьюпорте, светлая и тёмная темы.

| Компонент | Что есть |
|---|---|
| Backend | FastAPI + SQLAlchemy 2 (SQLite локально / PostgreSQL), семьи, приглашения, задачи, события, аналитика DAU |
| Web | React 19 + TypeScript + Vite + Tailwind 4, PWA, голосовой ввод через Web Speech API |
| Тесты | 20 тестов pytest (11 ядро + 9 API), ruff чистый, `npm run build` проходит |

Полное описание — [web-mvp.md](web-mvp.md).

> ⚠️ **MVP построен вокруг исходной гипотезы** (распределение дел, индекс невидимого труда). После интервью набор функций, скорее всего, изменится: этап 3/3 — прототип под подтверждённую проблему. Технический каркас (семья, приглашения, задачи, события, PWA, аналитика) переиспользуется в любом случае.

## 5. Следующие шаги

**Исследование (приоритет):**
1. Интервью с **организаторами** — начать с жён респондентов Р1 и Р2 (Р1 сам предложил).
2. Расширить выборку: семьи со школьниками, семьи, заботящиеся о пожилых, разные возрасты.
3. В конце каждого интервью — просить контакты знакомых (так набирается 20+).
4. После каждых 3–5 интервью — обновлять сводную таблицу и лист гипотез.
5. К 15.10 — выбрать персону и проблему (этап 2/3).

**Код (после этапа 2/3, не раньше):**
- Сузить MVP до функций must-have под выбранную проблему.
- Если подтвердится H-C (задачи рождаются в мессенджере) — Telegram-бот как основной канал ввода.
- Перед публичным запуском: вход через СберID / телефон вместо токена в браузере; голос через SaluteSpeech вместо Web Speech API (152-ФЗ); push-напоминания; деплой на Cloud.ru.

**Открытые вопросы к программе:** что считается «обращением» для метрики; какая система аналитики используется для оценки; засчитываются ли все члены семьи как отдельные DAU.
